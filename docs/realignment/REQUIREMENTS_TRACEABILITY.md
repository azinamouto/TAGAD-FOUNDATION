# Requirements traceability

Authority: complete user-supplied proposal, I–XIII; provenance in [README.md](README.md). **Every section is covered below, including non-software deliverables.** IDs are audit IDs, not proposal numbering. E01–E16 resolve to exact files and symbols in [VERIFICATION_BASELINE.md](VERIFICATION_BASELINE.md); D01–D13 resolve to [OPEN_DECISIONS.md](OPEN_DECISIONS.md); WP01–WP14 resolve to [IMPLEMENTATION_WORK_PACKAGES.md](IMPLEMENTATION_WORK_PACKAGES.md).

Status definitions: **verified** = the stated narrow behavior has executed evidence; **partial** = relevant implementation exists but the requirement has known gaps; **missing** = required capability not found in inspected active implementation; **unverified** = delivery, authority or effectiveness cannot be established. No row implies production verification. Proposal persona labels are not assumed to be implemented by the four technical role names.
