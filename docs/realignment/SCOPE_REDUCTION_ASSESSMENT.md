## Decisions, security and compatibility boundaries

V.1 User Management maps to administration; V.2 Data Encoding to registry; V.3 monitoring to programs/plans/accomplishments; V.4 Dashboard and Analytics to dashboard/sex-by-barangay chart; V.5 Report Generation to reports; V.6 Data Security and Privacy remains cross-cutting auth, validation, scope and audit, not an invented settings screen. Analytics/mapping navigation describes existing charts and unavailable mapping, not WP09/WP10 delivery.

Permitted fixes use already implemented ENCODER office restrictions, admin audit gate and body validators; D02 is not resolved or broadened. No new sensitive collection, suppression thresholds, public data, roles, dictionaries or releases. D03/D04 prevent new demographic/counting definitions; D05 prevents new sensitive workflow; D06/D09 prevent certified report/workflow claims; D07 prevents map; D08 prevents curated source selection by guesswork; D10–13 remain operational/adoption/budget blockers. Existing broader public/VIEWER permissions require D02/D05 review, not implied certification. WP02 is partial, not complete institutional acceptance.

Compatibility changes are intentional: malformed legacy writes become validation errors, unassigned encoder/missing-actor dashboard/report reads fail closed, database outages return errors instead of plausible statistics, empty-plan narratives remain incomplete. Hidden navigation is not an authorization boundary. Existing authorized deep links, imports, API paths, IDs and database structures remain.
